## 软件架构的常用分类

### 分层架构
这种架构将软件分为若干个水平层，每一层都有清晰的角色和分工，不需要知道其它层的细节。层与层之间通过接口通信，分层架构通常明确约束软件一定要分成多少层，最常见的是四层架构

1. 表现层：用户界面，负责视觉和用户交互
2. 业务层：实现业务逻辑
3. 持久层：提供数据，sql语句就在这一层
4. 数据库（database layer）：保存数据

### 事件驱动架构 event-driven architecture
是通过事件进行通信的软件架构，它分为四个部分

1. 事件队列 event queue：接收事件的入口
2. 分发器 event mediator：将不同的事件分发到不同业务逻辑单元
3. 事件通道 event channel：分发器与处理器之间的联系渠道
4. 事件处理器 event processor：实现业务逻辑，处理完成后会发出事件，触发下一步操作

### 微核架构
又称插件架构，是指软件的内核较小，主要功能和业务逻辑都能通过插件实现
内核通常只包含系统运行的最小功能。

### 微服务架构
微服务架构每个服务就是一个独立的部署单元，这些单元都是分布式的，互相解耦，通过远程通信协议联系。

微服务的三种实现模式
- RESTful API模式：服务通过api提供，云服务就属于这一块
- RESTful 应用模式：服务通过传统网络协议或者应用协议提供，背后是一个多功能应用程序
- 集中消息模式：采用消息代理，可以实现消息队列、负载均衡、统一日志和异常处理

### 云架构
主要解决扩展性和并发问题，最容易扩展的架构
高扩展性体现在将数据复制到内存中，变成可复制的内存数据单元，然后将业务处理能力封装为处理单元，每个处理单元都在内存里，需要进行数据持久化

云架构主要分为两部分：处理单元和虚拟中间件
1. 处理单元：实现业务逻辑
2. 虚拟中间件：负责通信、保持会话控制、数据复制、分布式处理和处理单元部署。
    - 消息中间件：管理用户请求和会话控制，当一个请求进来以后，它决定分配哪一个处理单元
    - 数据中间件：将数据复制到每一个处理单元，数据同步。保证每一个处理单元都得到同样的数据
    - 处理中间件：可选，如果一个请求涉及不同类型处理单元，则该中间件负责协调处理单元
    - 部署中间件：负责处理单元的启动和关闭，监控负载和响应时间，当负载增加，就新启动处理单元，减少则关闭


## 系统架构的常用建模方法
软件架构的模型可分为四种：结构模型、框架模型、动态模型和过程模型

- 结构模型：此方法以架构的构建、连接件和其他概念来刻画结构，研究结构模型的核心是架构描述语言
- 框架模型：侧重于整体的结构，框架模型主要以一些特殊的问题为目标建立只针对和适应问题的结构
- 动态模型：主要研究系统的“大颗粒“行为的性质，例如系统的重新配置或演化，这里的动态可以指系统的总体结构配置、建立或拆除通信或计算的过程。
- 过程模型：研究构造系统的步骤和过程，其结构是遵循某些过程脚本的结果。

4+1视角模型，通过逻辑视角、过程视角、物理视角、开发视角和场景视角来描述软件架构。
