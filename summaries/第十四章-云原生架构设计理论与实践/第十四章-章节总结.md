## 本章主线

本章讲**云原生**——一句话贯穿全章：

> **把应用里的"非业务代码"最大化剥离出去交给云设施，让业务代码变得轻量、敏捷、高度自动化。**

四节的推进逻辑是**「为什么 → 是什么 → 靠什么 → 怎么样」**：

> **14.1 为什么**（烟囱 → 瀑布 → 敏捷 → DevOps，一路解决"效率"问题）→
> **14.2 是什么**（定义、三大变化、**七大原则**、**七种架构模式**、三大反模式）→
> **14.3 靠什么**（容器/K8s、微服务、Serverless、服务网格四项技术）→
> **14.4 怎么样**（五个企业改造案例）。

**14.2 与 14.3 是一一对应的**——这是本章最好的记忆结构：

| 14.2 的原则/模式 | 14.3 的落地技术 |
| --- | --- |
| 弹性原则 + 所有过程自动化原则 | **容器 / Kubernetes** |
| 服务化原则 + 服务化架构模式 | **云原生微服务** |
| 弹性原则（到极致）+ Serverless 模式 | **无服务器技术** |
| Mesh 化架构模式 + 可观测原则 | **服务网格（Istio）** |

## 重点与难点

### 1. 重点：本章有五组"必须能默写"的名单

| 名单 | 口诀 / 内容 |
| --- | --- |
| **七大原则** | **拆 · 伸缩 · 看得见 · 扛得住 · 全自动 · 谁都不信 · 一直变** |
| **七种架构模式** | 服务化 / Mesh 化 / Serverless / 存储计算分离 / 分布式事务 / 可观测 / 事件驱动 |
| **K8s 五大核心能力** | **调度 · 部署 · 自愈 · 发现 · 伸缩** |
| **可观测三方面** | **Logging（多级别日志，开发者主动提供）· Tracing（前端到后端完整链路）· Metrics（量化多维度度量）** |
| **三大反模式** | **不拆不行 · 硬拆更糟 · 拆了不自动化＝自找麻烦** |

### 2. 难点：本章的易混对子

| 易混对子 | 分辨方法 |
| --- | --- |
| **可观测原则 vs 韧性原则** | **可观测＝"知道"**（看得见问题）；**韧性＝"抗住"**（出问题也不倒，目标是提升 **MTBF**） |
| **服务化原则 vs 服务化架构模式** | **原则**说"要拆"；**模式**说"怎么拆"（模块为粒度、接口契约、标准协议） |
| **Mesh 化架构模式 vs 服务网格** | 前者是 **14.2 的模式**，后者是 **14.3 的实现技术**（Sidecar + Istio） |
| **Logging / Tracing / Metrics** | **日志（谁记的：开发者主动）/ 链路（一个请求走了哪些服务，分布式尤其有用）/ 度量（量化多维度）** |
| **XA / BASE / TCC / SAGA / AT** | **XA 强一致慢 · BASE 快但挑场景 · TCC 可控但侵入 · SAGA 无 try 难维护 · AT 高性能零侵入** |
| **数据平面 vs 控制平面** | **数据平面＝Sidecar 代理（Envoy），真正转发流量**；**控制平面＝集中管理入口（Istiod），下发配置策略** |
| **反模式② vs 反模式③** | ②是**拆得不对**（数据还耦合、性能反降）；③是**拆了但没配套**（缺 CI/CD 自动化） |

### 3. 容易被忽略的三个细节

1. **定义里"非业务代码"不等于"三方软件"**——云代码三部分中，要剥离的是**处理非功能特性的代码**。
2. **Serverless 的"不适用场景"也是考点**：**有状态应用、长期后台密集计算、频繁外部 I/O**。
3. **零信任原则的关键措辞**：**IP 地址、主机、地理位置均不是可信凭证**，必须基于**认证和授权**。

## 一句话自测

> 合上书说一遍：**云原生就是把非业务代码最大化剥离、交给云设施接管，换来轻量敏捷高度自动化（14.2 定义）；它带来代码变简单、杂活交给云、交付全自动三大变化，遵循拆·伸缩·看得见·扛得住·全自动·谁都不信·一直变七大原则，落到服务化/Mesh 化/Serverless/存储计算分离/分布式事务/可观测/事件驱动七种模式，并要避开庞大单体、硬拆微服务、缺自动化三大反模式；支撑技术是容器与 K8s（调度·部署·自愈·发现·伸缩）、微服务（个体/横向/纵向 DSS/全局四类约束）、Serverless（全托管·通用·自动弹性·按量计费）、服务网格（Sidecar 把通信从业务里拆出来，数据平面 Envoy + 控制平面 Istiod）（14.3）；案例都是同一条链路——痛点、云原生手段、收益（14.4）。**
