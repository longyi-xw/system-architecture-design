# 1.1 系统架构概述

> 来源：《系统架构设计师教程》（第 2 版）· 第 1 章 绪论 · 1.1 节（含 1.1.1–1.1.4）

## 一句话概括

系统架构是系统整体的高层次结构表示，设计目的是通过一系列抽象指导系统各方面的设计与实现；本节讲发展历程、五种常用架构分类、四种建模方法、各架构风格的应用场景与发展主线。

## 核心概念

- 🟡 **系统架构**：系统是的一种整体的、高层次的结构表示。
- 🟡 **系统架构设计的目的**：对待开发系统做一系列相关抽象，指导系统各方面设计与实现；围绕可靠性、安全性、可移植性、可扩展性、可用性、可维护性。
- 🟢 **ENIAC**（1946）：世界第一台计算机，「电子数字积分器和计算机」。
- 🟡 **EDVAC**（冯·诺依曼结构计算机）：离散变量自动电子计算机，由**运算器、控制器、存储器、输入设备、输出设备**五部分组成。

## 发展历程（1.1.1）

- 🟡 起点：1968–1969 年两次 **NATO 会议**提出软件工程概念并发展其理论和方法。
- 🟡 三阶段：**基础研究阶段（1968–1994）→ 概念体系和核心技术形成阶段（1999–2000）→ 理论体系完善和发展阶段（1996–至今）**。

### 基础研究阶段

- 🟡 模块系统结构方法：数据结构设计法、功能分解法、数据流设计、面向对象设计。
- 🔴 模块划分规则：**最高内聚**（只实现一种功能 = 高内聚，三种以上功能 = 低内聚）、**最低耦合**、大小适度、调用链不过深、接口简单精炼且信息隐蔽、尽量复用已有模块。
- 🟡 MIS 管理信息系统在企业广泛使用；**SOA 面向服务架构**：基于一组标准方法和技术，整合复用现有应用系统和资源实现服务组件化，基于服务组件快速组装新业务应用，应对业务灵活性要求。

### 理论体系完善和发展阶段（五大研究方向）

架构描述与表示；分析、设计与测试；发现、演化与重用；开发方法；架构风格。

- 🟡 架构描述语言（ADL）：C2SADL（组件+消息）、Wright（分布并发）、ACME（架构互换）、UniCon（组件+连接）、Rapide（基于事件）；其他：Darwin、MetaH、Aesop、Weaves、SADL、xADL。
- 🔴 架构分析 6 方法：**SAAM 软件架构分析方法、ATAM 架构权衡分析法、CBAM 成本效益分析法、SBAR 基于场景的架构工程、ALPSM 架构层次可维护性预测、SAEM 软件架构评估模型**；架构分析分结构、功能、非功能三类；架构测试着重仿真系统模型、解决架构层主要问题。
- 🔴 **架构动态性** = 系统运行过程中导致的架构变化；**架构扩展** = 架构静态修改；二者同属架构适应性和演化范畴。架构发现 = 从既有系统中提取架构，属**逆向工程**。
- 🟡 基于架构的开发模型：**瀑布**（需求完全确认为前提）、**螺旋**（初期只有基本需求的渐进式）、**变换**（形式化方法为基础）。
- 🔴 软件架构风格 5 类：**数据流、调用返回、独立组件、虚拟机、仓库**。

## 常用架构分类（1.1.2）

- 🔴 **分层架构**（四层最常见）：表现层（界面与交互）→ 业务层（业务逻辑）→ 持久层（提供数据，SQL 在此层）→ 数据库层（保存数据）。层间通过接口通信，互不知细节。
- 🔴 **事件驱动架构**四部件：事件队列（接收入口）→ 分发器（分发到业务单元）→ 事件通道（分发器与处理器间渠道）→ 事件处理器（处理完再发事件触发下一步）。
- 🟡 **微核架构**（插件架构）：内核只含系统运行最小功能，主要功能和业务逻辑靠插件实现。
- 🔴 **微服务架构**：每个服务是独立部署单元，分布式、互相解耦、远程通信协议联系。三种实现模式：**RESTful API 模式**（服务经 API 提供，云服务属此类）、**RESTful 应用模式**（经传统网络/应用协议提供，背后是多功能应用）、**集中消息模式**（消息代理，可实现消息队列、负载均衡、统一日志和异常处理）。
- 🔴 **云架构**：解决扩展性和并发，最易扩展。数据复制到内存变成可复制的内存数据单元，业务能力封装为处理单元（数据在内存里，需要做数据持久化）。两部分：**处理单元**（业务逻辑）+ **虚拟中间件**（四种：消息中间件—管理请求与会话控制、分配处理单元；数据中间件—向各处理单元复制同步数据；处理中间件—可选，跨类型处理单元协调；部署中间件—处理单元启停、负载与响应时间监控）。

## 建模方法（1.1.2）

- 🔴 架构模型 4 种：**结构模型**（以构件、连接件刻画结构，研究核心是架构描述语言）、**框架模型**（侧重整体结构，针对特殊问题建立适应性结构）、**动态模型**（研究「大颗粒」行为：重新配置、演化）、**过程模型**（研究构造系统的步骤和过程）。
  > 备注：部分教材（张友生《软件体系结构》，不少题库出处）分 5 种，多「功能模型」，并称最常用的是结构模型和动态模型。
- 🔴 **4+1 视角模型**：**逻辑、过程、物理、开发 + 场景**五个视角描述软件架构。

## 应用场景（1.1.3）

🔴 架构风格 → 适用场景对照（高频考点，整表背）：

| 架构风格 | 适用场景 |
| --- | --- |
| 管道-过滤器 | 系统可分成若干独立步骤 |
| 主程序/子程序、面向对象 | 组件内部设计 |
| 虚拟机 | 构造解释器、专家系统 |
| C/S、B/S | 数据和处理分布在一定范围，经网络连接构成系统 |
| 平台/插件 | 具有插件扩展功能的应用程序 |
| MVC | 用户交互程序设计 |
| SOA | 企业集成 |
| C2 | GUI 软件开发，构建灵活可扩展的应用系统 |

## 发展未来（1.1.4）

- 🟡 架构发展主线：**模块化编程 / 面向对象编程 → 构件技术 → 面向服务开发技术 → 云技术**。
