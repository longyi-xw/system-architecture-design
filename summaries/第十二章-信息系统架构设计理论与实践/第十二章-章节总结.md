## 核心概念清单（🔴 为必背，详见各小节总结）

- 🔴 **ISA 定义**：对特定内容里的**信息**进行**统筹、规划、设计、安排**的有机处理活动；由**信息建筑师**设计，目的是**容易寻找与管理**，是一项**艺术与科学**｜出处 12.1
- 🔴 **物理结构二分**：集中式（好管但脆）vs 分布式（灵活但难协调）｜出处 12.2
- 🔴 **四种架构模型**：单机应用 → C/S → SOA → 企业数据交换总线｜出处 12.2
- 🔴 **C/S 四大类**：两层 C/S → 三层 C/S 与 B/S → 多层 C/S → MVC｜出处 12.2
- 🔴 **SOA 的本质＝消息机制或 RPC**（原文原句）｜出处 12.2
- 🔴 **企业数据交换总线＝连接器软件系统**（中间件或 CORBA/IIOP，银行电信常用）｜出处 12.2
- 🔴 **企业信息系统总体框架四层**：战略系统 → 业务系统 → 应用系统 → 信息基础设施（技术/信息资源/管理）｜出处 12.2
- 🔴 **ADM 十阶段**及"**需求管理居中横跨全程**""**阶段 E 是第一个直接关注实施的阶段**"｜出处 12.3
- 🔴 **国家信息化体系六要素**：资源·网络·应用·产业·人才·政策｜出处 12.3
- 🔴 **两种架构模式**：数据导向（BI/MDM）vs 流程导向（SOA）｜出处 12.3
- 🔴 **信息系统生命周期五阶段**及"**分析＝做什么＝逻辑设计**、**设计＝怎么做＝物理设计**"｜出处 12.3

## 重点与难点

### 1. 重点：本章有三条"必须能默写"的名单

| 名单 | 内容 |
| --- | --- |
| **四种架构模型 + C/S 四大类** | 单机 / C/S（两层·三层与 B/S·多层·MVC）/ SOA / 企业数据交换总线 |
| **ADM 十阶段** | 准备 → A 愿景 → B 业务 → C 信息系统 → D 技术 → E 机会与解决方案 → F 迁移规划 → G 实施治理 → H 变更管理 + 需求管理（贯穿） |
| **企业信息系统总体框架四层** | 战略 → 业务 → 应用 → 信息基础设施（技术/信息资源/管理） |

### 2. 难点：本章的易混对子

| 易混对子 | 分辨方法 |
| --- | --- |
| **系统分析 vs 系统设计** | **分析＝做什么＝逻辑设计（关键阶段，出系统说明书）**；**设计＝怎么做＝物理设计（出系统设计说明书）** |
| **横向综合 / 纵向综合 / 纵横综合** | **横＝同层跨职能**，**纵＝同职能跨层**，**纵横＝信息共享 + 模块化** |
| **CSF / SST / BSP** | **CSF 抓重点**（只利于定管理目标）、**SST 求全面**（重点不如 CSF）、**BSP 靠矩阵**（PO/RD/CU，中心是识别企业过程，无明显目标引出过程） |
| **数据导向 vs 流程导向架构** | 数据导向盯**数据模型与质量**（BI/MDM）；流程导向盯**端到端流程**（SOA），风险是缺完整数据模型 |
| **反作用力 vs 变革催化剂** | 反作用力＝**现实实现难**；变革催化剂＝**环境变了导致期望本身变**；两者合称**限制因素** |
| **C/S vs B/S** | 业务逻辑分布在两端 vs 主要集中在服务器端；胖客户端 vs 浏览器零维护 |

### 3. 容易被忽略的四个细节

1. **需求管理不是 ADM 的第 10 个顺序步骤**，而是**位于环的中心、横跨所有阶段**。
2. **阶段 E「机会及解决方案」是 ADM 中第一个直接关注实施的阶段**。
3. **"一软（工业软件）是核心"式的易错点在本章的对应物**：**ADM 是 TOGAF 六大组件中的核心**。
4. **架构六特征第 3 条**：**任何软件都存在架构，但不一定有文档表述**。

## 一句话自测

> 合上书说一遍：**ISA 是对信息做统筹规划设计安排（12.1，Zachman→FEA→TOGAF）；它长成物理上的集中式/分布式、逻辑上的横纵综合，落地为单机→C/S（两层/三层与B/S/多层/MVC）→SOA（本质是消息或RPC）→企业数据交换总线四种模型，装进战略/业务/应用/信息基础设施四层框架（12.2）；做法是 TOGAF 的 ADM 十阶段（需求管理居中，E 首个关注实施）加上信息化六要素、数据导向 vs 流程导向、生命周期五阶段与 CSF/SST/BSP（12.3）；最后用价值驱动的体系结构说明——限制因素（反作用力+变革催化剂）让期望值难以满足时，架构策略就是那艘船的舵和龙骨（12.4）。**
