## 本章主线

本章讲的是**软件体系结构设计中最常用的一种形式——分层**。全章结构极其清爽：

> **13.1 讲原理**（什么是分层、四层是哪四层）→ **13.2–13.5 自上而下把四层各讲一遍**（表现层 → 中间层 → 数据访问层 → 数据层）→ **13.6 换一个领域再讲一次分层**（物联网三层）→ **13.7 两个案例各验证一条主线**。

**一句话**：**分层的价值是"每层为上层服务、作为下层客户，且每层最多只影响两层"，代价是可能掉进"污水池反模式"。**

## 重点与难点

### 1. 重点：本章有四组"必须能默写"的名单

| 名单 | 内容 |
| --- | --- |
| **四层** | 表现层 / 中间层（业务层）/ 数据访问层（持久层）/ 数据层 |
| **表现层三模式** | MVC / MVP / MVVM |
| **工作流五接口** | 过程定义导入导出 / 客户端应用程序接口 / 应用程序调用接口 / 工作流机协作接口 / 管理和监视接口 |
| **五种数据访问模式** | 在线访问 / DAO / DTO / 离线数据模式 / ORM |

### 2. 难点：本章的易混对子

| 易混对子 | 分辨方法 |
| --- | --- |
| **MVC / MVP / MVVM** | **V 与 M 能否直连**：MVC 能；MVP 不能（过 Presenter）；MVVM 不能（过 ViewModel，且**双向绑定**） |
| **DAO / DTO / ORM** | **DAO＝谁来访问**（设计模式）、**DTO＝怎么运输**（数据容器）、**ORM＝怎么操作**（技术/框架）；**ORM 是实现 DAO 的手段** |
| **在线访问 / 离线数据模式** | **在线全程占着连接**；**离线取回即断，操作独立于连接与事务** |
| **数据中心型 / 文档中心型 XML** | **数据中心型规整、顺序无关**；**文档中心型零散、元素顺序有关** |
| **UIC / UIPC** | **UIC 是界面本身**；**UIPC 是界面背后的流程调度**（导航、工作流、事务、异常） |
| **网络层 / 应用层（物联网）** | 两层原文都提到"处理"，**应用层多了"人机交互"** |
| **通用 DataSet / 有类型 DataSet** | 通用胜在**灵活**；有类型胜在**编译时类型检查**（类型安全） |

### 3. 容易被忽略的三个细节

1. **分层的坑叫「污水池反模式」**——请求穿层而过却不做任何实际处理。
2. **物联网网络层的原文是"传递信息和处理信息"**，不是只负责传输。
3. **MVVM 的由来**是为解决 **MVP「UI 种类变多、接口不断增加」**的问题。
