## 本章主线

承接第 8 章"质量属性与架构评估"中的**可靠性**这一条运行期质量属性，把它单独展开成完整方法论，形成一个闭环：

**9.1 定义与度量**（可靠性是什么、怎么量化：MTTF/MTTR/MTBF、可靠度公式）→ **9.2 建模**（用什么数学模型描述它）→ **9.3 管理**（软件工程六阶段各做哪些可靠性活动）→ **9.4 设计**（怎么主动提高可靠性：容错/检错/降复杂度/系统配置）→ **9.5 测试**（怎么拿到可靠性数据）→ **9.6 评价**（用模型 + 数据得出结论）。

一句话概括：**先量化 → 再建模 → 定活动 → 做设计 → 拿数据 → 出结论。**

## 重点与难点

1. **重点**：9.1 的**计算题**与 9.4 的**辨析题**是本章两个得分点。计算题集中在 MTTF/MTTR/MTBF 关系与串并联系统可靠度（并联记"1 减全坏"，经典例题：三个 0.9 的子系统并联 = 1−0.1³ = 0.999）；辨析题集中在恢复块 vs N 版本的五个维度。
2. **难点**：**恢复块与 N 版本容易记反**。抓住底层直觉即可——恢复块是"一个个试，错了回退换下一个"（所以单机、动态冗余、后向恢复、慢），N 版本是"一起跑再投票"（所以多机、静态冗余、前向恢复、快）。另一个易混点是"**容错 vs 检错**"：容错能继续正确运行，检错只能发现并报警。
3. **待补强**：本章原始材料残缺严重，9.1 的指标体系、9.2 的建模主体、9.4 各技术的具体做法、9.5 的活动细节均靠检索补充。其中 9.1 的 MTBF 定义措辞与"MTBF=MTTF+MTTR"存在张力（⚠️ 已标注，两个独立来源措辞相同，应为教材原文本身如此）、9.4 的恢复块/N版本对照表未能核实是否为教材原文，建议翻实体书优先核对这两处。
